# L07 ResNet18 自检与通道数错误

## 这一集做了什么

把 L06 的 `ResBlk` 拼成 `ResNet18`：入口 `conv1`（3→64）+ 四个块（64→64、64→128、128→256、256→512）+ `fc(512, 10)`；先逐块打印形状做自检，确认通道骨架和尺寸，再故意用 3 通道原始图喂 `blk2`，复现通道数错误。

## 关键知识点

1. 通道骨架：`conv1` 把 3 通道升到 64，`blk1` 是 64→64（`extra` 为空），`blk2`、`blk3`、`blk4` 分别是 64→128、128→256、256→512（后三个靠 `extra` 的 `1×1` 卷积投影）。全部 `stride=1` + `padding=1`，所以 `32×32` 一路不变。

2. 卷积的 `in_channels` 是硬约束：`Conv2d(64, 128, kernel_size=3)` 的 weight 形状是 `[128, 64, 3, 3]`，喂进去的张量第 1 维必须正好是 64。RGB 的三通道只应该在入口 `conv1` 出现一次。

3. 自检要**逐块打印**而不是只看最终输出：某一块形状错了，逐块打印能立刻定位到是哪一层；如果只看最后一层报错，还得从头反推。

4. 维度债：`blk4` 输出 `[b, 512, 32, 32]`，展平后是 `512 × 32 × 32 = 524288`，而 `fc.weight` 是 `[10, 512]`。两边对不上，这是下一集要处理的——用 `stride=2` 降采样，最后再用全局池化收尾。

5. `forward` 里的 `fc` 是真的、也是暂时错的，但 `__main__` 只走到 `blk4`，所以没有触发维度崩溃。这不是把 bug 藏起来，而是按计划分两集处理。

## 我踩的坑

1. 坑1（真实复现）：现象：`RuntimeError: Given groups=1, weight of size [128, 64, 3, 3], expected input[2, 3, 32, 32] to have 64 channels, but got 3 channels instead`；原因：把原始 RGB 图直接喂给已经升维的 `blk2`，而它第一层卷积要求 64 通道；解决：3 通道输入只能进 `conv1`，后面每一块必须吃前一块的输出。

2. 坑2（从自检数字看出来，没崩）：现象：`flatten: torch.Size([2, 524288])` 对 `fc.weight: torch.Size([10, 512])`；原因：全程 `stride=1`，没有任何降采样，`512 × 32 × 32` 这个维度太大；解决：L08 给 ResBlk 加 `stride`，L09 用 `F.adaptive_avg_pool2d(x, [1, 1])` 收尾。

3. 坑3（读报错的方式）：现象：整段 traceback 十几行，真正有用的只有最后一行错误类型和最后一个属于自己文件的调用点；原因：中间大部分是 `module.py` 里的框架转发；解决：定位错误先看最后一行，再往回找第一个 `pytorch-cv-learning/lessons/...` 的行号。

## 运行方式

在仓库根目录执行，纯形状自检，CPU 上秒级完成。复现 bug 2 时在末尾临时加两行（已删除，报错见「我踩的坑」）。

```bash
source ~/code/pytorch-env/bin/activate
python lessons/L07/main.py
```

## 输出

```text
conv1 : torch.Size([2, 64, 32, 32])
blk1  : torch.Size([2, 64, 32, 32])
blk2  : torch.Size([2, 128, 32, 32])
blk3  : torch.Size([2, 256, 32, 32])
blk4  : torch.Size([2, 512, 32, 32])
flatten: torch.Size([2, 524288])
fc.weight: torch.Size([10, 512])
```

## 我的理解

ResNet18 的骨架就是"入口升到 64 通道，再让四个块把通道逐层翻倍"；自检留下两个必须记住的数字——`512 × 32 × 32 = 524288` 太大，接不上 `fc`，而且卷积只认通道契约，喂错通道不会自动纠正。
